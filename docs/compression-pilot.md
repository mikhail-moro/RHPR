# Pairwise history compression pilot

Run `experiments/yambda_pairwise_compression_pilot.json` through the existing
Kaggle workflow, on GPU, with kernel override
`carasik/rhpr-pairwise-compression-pilot`. The bundle is private, embeds the exact
Git revision and attaches `ploshkin/yambda`; Internet stays disabled.

The four variants are Full/OFF, PairMLP/OFF, Full/ON, PairMLP/ON. All start from
the recipe in the actual `best-config.json` output of
`carasik/rhpr-yambda-sasrec-search`: d256, four layers/heads, FFN x4,
dropout0.2, LR0.001129959000566945, weight decay1e-5, physical batch8,
effective batch128, sampled softmax512, seed42. The epoch limit10 and patience2
are starting limits; `best_at_epoch_limit` flags unresolved convergence.
This pilot performs no new HPO and does not evaluate test.

## Model and training

Preserve the last128 observed events, merge adjacent pairs in the older prefix,
and retain an odd singleton. At length1028 this gives450 summaries +128 raw
events. PairMLP uses `mean(a,b) + GELU(Linear([a;b]))` with one512->256
projection, zero-initialized after the backbone. The valid output axis is
physically shortened, with padding on the right. Mean and Recent controls are
implemented for later comparison but are outside this four-variant temporal grid.

PE follows compression and preserves raw recency: `n-1-source_position`, using
the right endpoint of each pair. Gap embeddings, when enabled, are added before
compression. Timestamps are explicitly seconds; observed gaps are computed before
cropping and log-bucketed, with a separate START bucket. Target timestamps are
never inputs. Unit/missing-data errors fail explicitly.

All variants supervise the same last min(n,128) raw positions. The loss mask is
separate from attention validity; old summaries get gradients through attention.
The classifier processes only selected tail states. Uniform512-negative sets are
shared within a sequence and generated by a dedicated generator so different
dropout shapes do not alter the negative draws. Common backbone initialization
and user order are matched across variants. The encoder remains causal.

## Quality

Each validation user has one held-out next item. The encoder computes all states
in parallel, then only the last valid state ranks the entire catalogue in FP32,
with chunked top10. That query sees all128 raw tail events. Repeated items remain
valid candidates. Report NDCG@10, Recall@10, counts and fixed length cohorts;
each variant's checkpoint is selected only by validation NDCG.

## Time, FLOPs and memory

Measure history processing (including compressor/packing), scoring+top10, and
the combined call independently. Inputs/weights are already on device; CPU data
preparation, transfer, external storage, serving/network and KV caching are
outside this scope. Eval/inference mode, equal precision/hardware,30 warmups,
200 wall-time B1 samples with CUDA synchronization, and strict physical B32
throughput are required. Fixed128/512/1028 and identical sampled validation
histories are recorded. Profiler runs separately from timing.

Nominal dense matmul FLOPs use multiply-add=2 and actual executed padded shapes:
`BL[(8+4r)Td²+4T²d]`, plus `4Pd²` pair projection and `2BVd` catalogue scoring.
At B1,d256,L4,r4 the history count is10.7962G for Full and5.1228G for PairMLP
at length1028. This excludes non-matmul operations and does not promise a2.11x
wall-time speedup. Unsupported fused profiler counts are marked, not treated as
zero work. Memory peaks reset after warmup for each measured stage; optimizer
buffers are released before inference. Train throughput/time/memory are separate.

## Diagnostic artifacts

Per-user top10/quality is paired by user, split, context hash and target. History
features use one frozen Full/OFF item embedding table: actual/window/output
lengths, exact-pair cosine distances, dispersion, repetition, old/tail overlap
and observed gaps. Answer-dependent target-repeat/popularity fields live only in
prediction diagnostics. They are not router features.

Quartiles of pair distance and old uniqueness are fitted on validation and
saved; paired deltas, four hit/miss cases, counts and user-bootstrap intervals
are reported within length groups. These exploratory intervals describe fixed
checkpoints; one seed does not establish training variance or adaptive-depth benefit.
No diagnostic work occurs inside the latency timer.

Root artifacts include finite flat `metrics.json`, `summary.md`,
`run-manifest.json`, `pilot-results.json`, per-run config/checkpoint/history/
prediction/benchmark/profiler files, shared history-features and prediction
JSON/Parquet, `diagnostic-reference.json`, `feature_bins.json`, paired-user and
cohort Parquet, and `cohorts.json`. Partial suite status is persisted; the complete
flag becomes true only after all four variants and diagnostics finish.

## Verification

Run `python3 -m unittest discover -s tests -v` with Torch/NumPy/Polars installed.
Tests cover causal future perturbations including timestamps, source coordinates,
ragged padding, shared initialization/sampling, compact classifier shapes,
gradient flow, observed gap slicing, exact chunked ranking, benchmark contracts,
paired joins/frozen bins and a real four-variant tiny CPU training run.
