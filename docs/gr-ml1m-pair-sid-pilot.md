# ML1M pair SID compression pilot

Question: can a mini-TIGER preserve next-item ranking when the older half of its history is represented by three semantic tokens per ordered pair instead of four tokens per individual movie? A negative result is a valid result.

Uses the frozen clean ML1M cohort and raw windows: 151166 train examples, 2786 validation users, up to 20 history movies. It does not evaluate test. For each history, remove padding, take floor(length/2) oldest movies, combine adjacent non-overlapping pairs left to right and preserve an unpaired final old movie. Recent movies remain unchanged. The pair is described as `First movie: {title+genres} Second movie: {title+genres}` using the pinned Sentence-T5; each ordered pair is cached once. Train has 121129 unique pairs, validation 13134, union 124812. The quantizer is fit uniformly on distinct training pairs, excluding pairs present only in validation; those are encoded using the frozen model. Context timestamps can tie: within-timestamp ordering is the existing item-ID tie-break, not evidence of watch order.

Train GRID normalized residual mini-batch KMeans separately on the 2874 item representations and train pair representations, 3x256, 10 passes per level. Use seeds 42 and 101. Film SIDs include a fourth collision suffix, used on both sides as both input and decoder target. Pair SIDs have three semantic codes and no suffix: distinct pairs may collide. Pair token embeddings use a disjoint 3x256 input table. The table is installed for both control and pair to ensure identical named-parameter initialization within each seed; it receives gradients only for pair inputs. Saving the pair keys, embeddings, train mask, centroids, codes, diagnostics, per-epoch curves, predictions, best/last checkpoints and SHA provenance permits analysis and reuse. Pair histories use a padded 56-token array because a 19-item input can contain 56 tokens (a full 20-item history contains 55); control uses 80. Padding is masked.

Four mini-TIGER trainings: control/pair, seeds 42/101 for both quantizer and generator, 30 epochs, validation every 5, FP16, SDPA, Adam 1e-3, effective and physical batch 512. Paired models use exactly the same individual-movie index and same generator initial weights within each seed. Seed comparisons confound generator and quantizer seeds: this is a screen, not a variance decomposition. Always compare fixed epochs and validation-selected metrics, and do not claim convergence or causal compression without further controls. Sentence-T5 preprocessing and the frozen pair quantizer are an additional cost; evaluate training/serving latency end to end before claiming an efficiency win. No test access.

## Seed 42 recovery

The original v1 completed the frozen item and pair indexes for both seeds. Worker 0 failed before completing control_42: only 32.81 MiB of its T4 was free while a separate session process occupied 14.29 GiB. Worker 1 completed control_101 and pair_101. Parent-side CUDA allocator retention from pair-index staging is a likely cause; the log alone does not identify the other process conclusively. The original failed and has no successful metrics/manifest. Original pair embeddings were retrieved locally. The recovery copies the exact completed seed-42 `items`, `pair-keys`, `pairs` and index diagnostics into a private manifest-verified dataset pinned by SHA; it runs only control_42 and pair_42 concurrently on the two T4s. It checks at least 8 GiB free on each GPU before starting either worker and does no embedding or quantizer fitting. Original seed-101 results remain untouched. An allocator cleanup was also added to the original full pilot between index construction and generator workers.

## Three-seed continuation to epoch 50

User authorized extending the pilot from 30 to 50 epochs and adding seed 202. Train control and pair for seeds 42 and 202 from scratch for 50 epochs, while resuming the original control and pair seed 101 at completed epoch 30 (20 additional epochs). Run validation every 5 epochs and select by validation NDCG@10. Preserve raw clean windows, title+genres, separate item/pair 3x256 GRID RQ-KMeans, mini-TIGER configuration, FP16/SDPA, and physical/effective batch 512. Max and minimum epochs are 50: no intermediate early stop. No test access.

The private continuation input contains SHA-256 pinned copies of the original seed-42 and 101 frozen SID matrices, pair keys, item embeddings, all 124812 pair embeddings, the training-pair mask, and both complete seed-101 checkpoint histories. Seed-202 RQ-KMeans uses only train pairs and the saved T5 embeddings. Its fitting executes in a dedicated GPU subprocess that exits before any generator worker starts, releasing device memory. Worker 0 runs control42, resumed pair101, pair202; worker 1 runs pair42, resumed control101, control202. The original models restore model and Adam/scaler/random state, verify old index/hash and matching configuration, retain previous curves and prediction files, and verify continuation begins at epoch 30. A deterministic CPU test confirmed equivalence to uninterrupted miniature GRID training for this restore path; CUDA's exact numerical determinism across machines is not guaranteed. Validation-selected per-seed comparisons are exploratory and include checkpoint-selection uncertainty.

The initial 50-epoch kernel v1 failed during seed-202 index construction, before any generator training: applying the frozen centroids did not exactly reproduce fitted training-pair codes. Fitting uses direct squared `torch.cdist` with `donot_use_mm_for_euclid_dist` in bounded chunks, while the original replay used default `torch.cdist` (which can use GEMM and suffer cancellation). The replay now uses the exact fitting distance implementation and retains the exact-equality guard; the precomputed 42/101 indices are not recomputed. A unit test pins the backend, and a CPU replay of cached seed-42/101 centroids matched 256 sampled train/validation pairs per seed. The source checkpoint dataset is unchanged.
