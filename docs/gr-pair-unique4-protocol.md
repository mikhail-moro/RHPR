# MovieLens1M pair representations with 3+1 SID

Paired study: Pair20, Recent15 and Full20, seeds 42/101/202. Each receives the same initialized 4+4 d64 mini-TIGER, training examples, fixed item index, 50 epochs and validation every five epochs. Pair20 uses five pair SIDs and ten single-item SIDs; Recent15 uses fifteen single-item SIDs. Both use sixty history-token positions. Full20 uses eighty. All three allocate the same pair-input embedding table, even where unused, to preserve initialization and parameter budget.

The pair quantizer's three learned codes are the byte-pinned codes of the previous pair-SID run, including test-history pairs encoded with frozen centroids. For each three-code prefix, append a zero-based ordinal to make every pair SID unique. Allocate suffixes in three stages: training pair keys first, other previously cached validation keys second, new test-history keys last; within each stage keys are sorted. Later stages cannot modify existing assignments. Refuse a prefix group of 257 or more pairs. This policy does not use held-out target labels, but the ordinal is arbitrary and online allocation order must be specified; it is not semantic information or a proven serving implementation.

Test is evaluated for epoch 50 and the validation-selected checkpoint; it was already inspected in earlier exploration, so it is not an untouched confirmatory holdout. Record distinct pair collision groups, maximum suffix, unused suffix IDs on evaluation histories, and validation and test predictions. Existing 3-code pair checkpoints are incompatible and are not resumed.
