# Historical experiment result ledger

This ledger preserves the nine available run-output snapshots from the closed history-compression/QSSM chain. It complements the final music-data reports and does not register further experiments. The full original private outputs remain outside Git.

**These runs are not one matched leaderboard.** Early searches reused the same final training target block; history continuation warm-started selected models; the last QSSM/FuXi and QSSM2 runs used fresh rotating-window training. A proxy metric can describe a reused historical control. Full-transfer evaluation can change inference length without retraining. Never infer that every numeric field came from a fresh arm in the named run.

Each metrics file is copied byte-for-byte, checked for a flat object of finite scalar values, and paired with a whitelist-only provenance extract. SHA256 and byte counts are retained in each provenance file and the [summary index](run-summaries/index.json). The original full run manifests, checkpoints, per-user/per-anchor records and input arrays are not copied.

## Reading the snapshots

- `query-architecture`: compare CA and QSSM only under the registered fixed-block/proxy/full-transfer selection. Its K4 CA winner is not an equal-budget rotating CA baseline.
- `baseline-screen`: contains the Recent128, QueryOnly, Mamba4Rec and FuXi family screen alongside historical query-family references. Check each field suffix and `final-selection.json`; `full_transfer` is not full-history training.
- `qssm-search`: preserves the K/architecture search that selected the K32, inner64/state16/slow-step QSSM. Its larger historical metrics must not be substituted for a later fresh rotating QSSM result.
- `history-qssm` and `history-fuxi`: report 20-pass continuations from selected weights. QSSM has short/full controls; FuXi intentionally reuses its historical short control to save quota. These do not isolate training length under a common fresh initialization.
- `mamba-ablation`: contains fresh feature results plus a reused base; generic selected-family fields and feature-specific fields have different meanings.
- `ssm2-benchmark`: timing/memory/native-kernel audit only. `quality_metrics_computed` is false; a faster microbenchmark does not establish recommendation quality.
- `rotating-qssm-fuxi`: use `query_ssm_m32_rotating_ndcg10/100` and `fuxi_linear_rotating_ndcg10/100` for the fresh shared-schedule results. Generic `*_proxy_*` values can retain fixed-block controls.
- `ssm2-state128`: use `query_ssm2_m32_s128_proxy_ndcg10/100` for the one newly trained arm; the final comparison is documented in the [closure README](README.md) and [paired analysis](aggregates/qssm2-research-results.json).

All quality runs are exploratory validation-based, single-seed investigations. Read exact target/window and stopping registrations before comparison. Earlier full-history comparisons, optimizer resets, numerical execution changes and checkpoint selection confound cross-run conclusions. A training pass is not necessarily a complete event epoch. These snapshots are preserved as evidence rather than a claim of converged architectural ranking.
